# PROMPTS — what was asked of Claude, and what was done with the answer

This file records the prompts used to build the video. It is not a transcript, and no
Claude conversation is reproduced here (the course's GitHub rubric excludes private
conversations from the submission).

**No Claude API call was made by this project.** No model generated any number, image,
or audio in this video. Narration is local Kokoro TTS; all figures come from the
course's own Python.

---

## 1. Inspect before building

> Inspect the working directory, locate the Brutalist toolkit and the INFO 7375 course
> checkout, read the README/CLAUDE.md/HOW-TO and the full `ai-explainer` SKILL.md, find
> `lessons/01-randomness-and-first-prompts/code/main.py`, run it, and capture the actual
> output. Do not assume the repository structure.

**Result / what I did with it:** located both inputs as zips in `~/Downloads`. Ran
`main.py` → the probabilities and seeded counts now in `evidence/`. Ran the six lesson
tests → all pass. Found that the concept I had chosen is the chapter's own section
heading at `:192`, which set the framing for the whole script.

## 2. Verification before narration

> Build a verification table: for each claim, name the source, whether it is verified,
> and the exact evidence. Do not proceed if a central claim cannot be verified. Never
> invent a numerical example and present it as Chapter 1 evidence.

**Result:** `FACTCHECK.md`. Thirteen conceptual claims and nine numerical ones, all
traced. The key outcome was discovering the video needed **no** invented numbers — the
chapter supplies the logits, the temperatures and a recorded results file. I wrote
`scripts/verify_temperature.py` to prove our table matches `research/worked-examples.json`
exactly rather than merely asserting it.

## 3. Resolving the branding conflict

> The toolkit's `ai-explainer` bookends hardcode `@NikBearBrown` and a "Liam, in for
> Bear" narrator line. The course prerequisite says not to imply instructor endorsement.
> Which wins?

**Result:** the course rule wins. I used the toolkit's engine (Kokoro clock, Remotion
render, `compile.py` assembly, QC gates) with my own `aperture` palette and my own
closing card. Setting `metadata.palette` to something other than `claude` also disarms
`compile.py::lint_skin`, which would otherwise require the locked bookends. Recorded in
`FRICTIONAL.md`.

## 4. Scene authoring

> Search the existing scene library before proposing custom visuals.

**Result:** ran `./art scenes` against the 610-entry index. The library's chart
components are built for the Claude cream palette and for categorical bar data, not for
a three-stage numeric transformation with a temperature variable. I wrote eight new
components rather than bending an existing one, and documented each with a JSDoc header
so `./art scene-index` can index them properly.

> Build an animation in which the logits appear, temperature appears as a variable, the
> transformation is calculated, and the probabilities visibly change as temperature
> changes. Do not hard-code fabricated results.

**Result:** `TempHook`, `TempScores`, `TempDivide`, `TempSoftmax`, `TempTriptych`,
`TempRatio`, `TempBoundary`, `TempClose`. Every prop is generated by
`scripts/build_beat_sheet.py` from `numbers.json` — there is no path by which a number
reaches the screen without passing the verification script first.

## 5. Timing correction (the one substantive revision)

> The scene animations all finish in about five seconds, but the narration runs twenty
> to twenty-six seconds per beat.

**Result:** this was my own observation from reading the first rendered stills, and it
was the most important fix in the build. Every reveal was re-expressed as a *fraction*
of the beat (`useAt()`), and `calculateMetadata` in `Root.tsx` now feeds each
composition the measured mp3 duration, so motion tracks speech instead of finishing
early. See `REVIEW.md`.

## 6. Narration rewriting for speech

Mathematical expressions were rewritten to be spoken rather than read: "e to the one
over T" instead of "exp(1/T)", "twenty-four and a half percent" instead of "24.47%".
The displayed value keeps full precision; the spoken value is rounded and says "about".

## The suggested prompt for a viewer

A viewer who wants to take this further:

> I am studying how sampling temperature works in language models. I understand that
> softmax turns scores into probabilities, and that the ratio of any two probabilities
> is e to the power of their score difference divided by T. Walk me through
> (1) why subtracting the maximum score leaves the distribution unchanged,
> (2) what happens to that ratio as T approaches zero and as T grows large, and
> (3) why a more concentrated distribution is still not evidence that the top-ranked
> answer is correct.

This prompt is offered as a starting point. It was not run to produce anything in this
video.
